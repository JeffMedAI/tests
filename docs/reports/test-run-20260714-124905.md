## WHAT FAILED / FINDINGS (each with severity)

1. **[HIGH — FIXED this session] Home page and Requests page crash (500) — refactor bug.**
   `alert_row_to_display` was moved into `alert_queries.py` but `main.get_urgent_attention`
   (main.py:1406) still called it without importing it → NameError → 500 on `/` and `/requests`
   whenever a critical alert exists. The 323 unit tests missed it; the e2e suite (not run during
   the refactor) catches it. **This has been LIVE on production since 13 July** (the bug shipped
   before the current production process started). Fixed on-branch: added the import + a
   regression test. Logged in CHANGELOG.

2. **[HIGH — OPEN] Global search is broken on every page — silent.** `/api/search`
   (routers/analytics.py:~141) queries a `batch_id` column that does not exist in the `cases`
   table → 500. The "/" command-palette search sits on every page; the front end **swallows the
   error silently**, so staff just see "no results" and never report it. Confirmed 500 on BOTH
   production and the refactor branch. Needs a fix + a visible error on search failure.

3. **[MEDIUM — OPEN] Notes-gate is bypassable on the main resolve path.** Red-flag/identity cases
   are correctly blocked (HTTP 400) if you resolve via the quick-action button
   (cases.py:559), but the full update form auto-fills a default note (cases.py:455) *before* the
   check (cases.py:464), so that path resolves a red-flag/identity case **without staff notes**,
   using boilerplate. The testing rules require this to be blocked. Server-side enforcement should
   match the quick-action path.

4. **[MEDIUM — OPEN] Red-flag detector over-triages on the word "faint".** The near-silent test
   call contained "faint rustling" and was escalated to 999 Emergency ("POSSIBLE EMERGENCY -
   fainting"). The detector matches `\bfaint\b` (word-safe, not raw substring) but is blind to
   meaning — it treats the adjective "faint" (quiet) the same as fainting (collapse). Same risk
   for "sweating", "stroke", "collapse". Direction is fail-safe (over-escalate, never miss), but
   it creates alarm-fatigue noise. Suggest context-gating the weak words.

5. **[MEDIUM — OPEN, test-data gap] Red-flag test fixtures used canned symptoms.** The structured
   red-flag cases (stroke/sepsis/MH) all carried the same injected `red_flags_mentioned`
   ("chest pain, breathlessness, sweating"), so the staff task line reads the wrong symptoms for a
   stroke/sepsis/suicidal call, and the per-type extraction path was **not genuinely exercised**.
   Fix the fixtures so each red-flag case carries its own realistic symptoms.

6. **[LOW] Duplicated code from the split.** `clean_alert_message` and `is_modal_worthy_alert`
   exist in BOTH main.py and alert_queries.py — divergence risk.

7. **[LOW] Deadletter mislabel.** Re-submitting an already-processed call (which happened here via
   a retry) is correctly deduped, but the deadletter manifest labels it `permanent_failure`, which
   will false-alarm production monitoring. Suggest a distinct `duplicate_skipped` reason.

8. **[LOW] Mock NHS numbers look real.** The synthetic lookup uses checksum-valid NHS numbers with
   real-allocation prefixes rather than the reserved 999-test range. Regenerate in the test range.
