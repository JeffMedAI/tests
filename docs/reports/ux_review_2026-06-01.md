## CRITICAL Issues (Fix Before Pilot)

### C1 — Emoji Used as UI Icons
**Pages:** Dashboard (h1, h2, sidebar link), Requests list  
**Found:** `📊 Today's Overview`, `⚠️ Urgent Attention`, `🚨 Critical Issues`, `👁️ Cases Needing Review`  
**Problem:** Emojis render inconsistently across OS/browser, are not styleable, scale poorly, and screen readers announce them verbosely ("chart with upwards trend and dollar sign" instead of "Dashboard").  
**Fix:** Replace with inline SVG icons from Heroicons or Lucide. The `⚠️` warning emoji is acceptable ONLY in user-generated content, not in UI chrome.  
**Effort:** Low — global find/replace in templates.

### C2 — Focus States Suppressed (`outline: none` detected)
**Pages:** All pages  
**Problem:** CSS contains `outline: none` without a `focus-visible` replacement. Keyboard-only users (including reception staff who use Tab to navigate quickly) lose all visual indication of their position on the page.  
**Fix:** Add `focus-visible` ring to all interactive elements. At minimum: `*:focus-visible { outline: 2px solid #0891B2; outline-offset: 2px; }`.  
**DCB0129 relevance:** H2 control (human dual-check) requires staff to clearly see and interact with review buttons.

### C3 — Touch Targets Below 44px Minimum
**Pages:** All pages — sidebar nav, filter tabs, chart links, icon buttons  
**Found:**
- All sidebar nav links: **30px tall** (Dashboard, Requests, Patients, Staff, Reports, Settings)
- Date range toggles (Today/Week/All): **25px tall**
- Chart request-mix links: **23px tall**
- Import/Import button: **32px tall**
- Notification badge button: **28px tall**
**Impact:** Critical for tablet/touch use. A nurse or receptionist with acrylic nails or in a hurry will misfire regularly.  
**Fix:** Set `min-height: 44px` on all nav links and interactive rows. Add `padding: 7px 12px` to sidebar links.

### C4 — Body Font Size 14px (Below 16px Minimum)
**Pages:** All pages  
**Problem:** Body text, table cells, and paragraph text render at 14px (some table cells at 11–12px). On mobile this is unreadable without zooming. NHS staff often work on mounted screens at distance.  
**Fix:** Set `font-size: 16px` on `body`. Table cells can stay at 14px on desktop but must respect browser zoom. Table cells at 11px (case list timestamps) need to be at minimum 12px with sufficient contrast.

### C5 — Missing Skip Link
**Pages:** All pages  
**Problem:** No "Skip to main content" link. A keyboard user must Tab through the entire sidebar (6 nav items + sub-links + status cards = ~25 tabs) before reaching the case list on every page load.  
**Fix:** Add `<a href="#main-content" class="skip-link">Skip to main content</a>` as the first focusable element in the layout, visible on focus.

## HIGH Priority Issues

### H1 — No Breadcrumb on Case Detail Page
**Page:** `/case/{id}`  
**Problem:** The page title shows `E2E-20260601-135250-01-PRESCRIPTION — JeffLocal Staff Dashboard` — the call ID, not the patient name. The H1 correctly shows the patient name, but the browser tab title (shown in taskbar) and the back-navigation ("← Back to Requests") give no context about where you came from or what filter/page you were on.  
**Impact:** If a receptionist opens 5 case tabs, all tabs show opaque call IDs. No way to tell from the tab which patient is which.  
**Fix:**  
1. Page title: `{PatientName} — {RequestType} — JeffLocal`  
2. Breadcrumb: `Requests › {PatientName}` with `aria-label="breadcrumb"`  
3. Back link preserves the originating filter/page URL (already partially implemented via `return_url` — ensure it always works).

### H2 — Tab Interface on Case Detail Has No ARIA Role
**Page:** `/case/{id}` — Action Needed / Conversation / Triage / Audit tabs  
**Problem:** The tab switching UI has no `role="tablist"`, `role="tab"`, or `role="tabpanel"` attributes. Screen readers cannot announce or navigate tabs. Keyboard users cannot use arrow keys to switch tabs.  
**Fix:** Apply ARIA tab pattern: `role="tablist"` on container, `role="tab"` + `aria-selected` on each tab button, `role="tabpanel"` + `aria-labelledby` on each panel. Tab key enters the tab list; arrow keys navigate between tabs.

### H3 — PIN Input Has No Label
**Page:** `/login` — PIN tab  
**Problem:** The PIN input field (`input[type="tel"]`) has no `<label>`, no `aria-label`, and only a placeholder `"••••"`. When focus enters the PIN field, a screen reader announces nothing useful. The placeholder disappears when typing begins.  
**Fix:** Add `<label for="pin">4-digit PIN</label>` or `aria-label="Enter your 4-digit PIN"`.  
**Note:** This touches auth flow — flag for Saeed approval before changing login behaviour.

### H4 — Sidebar is Always Visible on Mobile (Covers Content)
**Page:** All pages at 375px  
**Problem:** The sidebar (280px wide) is always rendered `display: flex` on mobile, pushing or overlapping the main content area. The viewport is only 375px, leaving only ~95px for content — effectively unusable.  
**Fix:** On mobile (`< 768px`), hide the sidebar by default; show it via a hamburger toggle. Navigation items should collapse to a bottom navigation bar or slide-in drawer.

### H5 — Filter Tabs Have Overflow Elements Clipped Off-Screen on Mobile
**Page:** `/requests` at 375px  
**Problem:** Links in the filter tab area have `right` values of 405–778px on a 375px viewport. They are scrollable but not visually indicated as such (no scroll indicator, no fade).  
**Fix:** Add `overflow-x: auto; -webkit-overflow-scrolling: touch;` with a right-fade gradient on the tab bar, or collapse filters to a dropdown on mobile.

### H6 — "Forgot password or PIN?" Link is Only 14px Tall
**Page:** `/login`  
**Problem:** The forgot-password link measures 14×133px — far below the 44px touch target minimum and also below the 24px minimum for secondary actions.  
**Fix:** Add `padding: 12px 0` to increase touch target without changing visual size.

### H7 — No Password Visibility Toggle
**Page:** `/login`  
**Problem:** Password field has no show/hide toggle. Staff who mistype their password (e.g. Caps Lock on) have no way to verify what they typed, leading to unnecessary lockouts (5-attempt limit).  
**Fix:** Add a toggle button with `aria-label="Show password"` / `"Hide password"` and a visible eye icon. This touches auth flow — flag for Saeed approval.

### H8 — Case List Item Heights Inconsistent (166px vs varying)
**Page:** `/requests`  
**Problem:** Request card height varies significantly based on content — cards with identity warnings, red flags, and multi-line summaries are much taller than simple prescription cards. This makes the list feel unstable and makes it hard to scan at speed.  
**Fix:** Standardise card layout with a fixed minimum height and truncate long AI summaries to 2 lines with `overflow: hidden; display: -webkit-box; -webkit-line-clamp: 2`.

### H9 — Badge/Chip Font Size at 10px
**Page:** Dashboard (notification badge)  
**Problem:** The critical-issues badge shows count in 10px text on a 28×32px button. At 10px, this fails WCAG AA (minimum 12px for inline text in interactive elements).  
**Fix:** Increase badge font to 12px minimum. Ensure badge has `aria-label="4 critical issues"` on the parent button.

## MEDIUM Priority Issues

### M1 — Heading Hierarchy: H1 Uses Emoji Prefix Globally
**Pages:** Dashboard h1 (`📊 Today's Overview`), alert h2 (`⚠️ Urgent Attention`)  
**Problem:** Screen readers announce the emoji character names first, disrupting heading navigation flow. Screen reader users rely on heading navigation to jump between sections.  
**Fix:** Move emoji inside a `<span aria-hidden="true">` wrapper: `<h1><span aria-hidden="true">📊</span> Today's Overview</h1>` as an interim fix. Long-term: replace with SVG icons.

### M2 — No ARIA Live Region for Real-Time Data Updates
**Pages:** Dashboard (case counts, workload numbers)  
**Problem:** The dashboard shows live case counts (Open: 10, Critical: 2) but none of these update dynamically with an `aria-live` announcement. If counts change after page load (e.g. after import), screen reader users are not notified.  
**Fix:** Wrap key metric counters in `<div aria-live="polite" aria-atomic="true">` so count changes are announced.

### M3 — Copy Buttons Lack Specific Context
**Page:** `/case/{id}` — Copy Identifiers, Copy Record Note, Copy Staff Task, and three unlabelled "Copy" buttons  
**Problem:** Three "Copy" buttons in the identifiers panel have no distinguishing text or `aria-label`. Screen readers announce all three as "Copy" with no context of what is being copied (EMIS number? NHS number? Callback number?).  
**Fix:** `aria-label="Copy EMIS number"`, `aria-label="Copy NHS number"`, `aria-label="Copy callback number"`.

### M4 — Search Input on Requests Page Has Whitespace-Only Label
**Page:** `/requests`  
**Problem:** The search input's associated label element contains only whitespace characters (detected as `"\n          \n        "`). Visually the search box is unlabelled; programmatically the label exists but announces nothing.  
**Fix:** Ensure label text is non-empty: `<label for="search">Search requests</label>`.

### M5 — Requests List: No Empty-State Design
**Page:** `/requests?filter=resolved`  
**Problem:** No `empty-state` component detected. When a filter returns zero results, the page shows a blank content area with no explanation, no CTA, and no illustration.  
**Fix:** Add an empty-state component: icon + "No cases match this filter" + a "Clear filters" CTA button.

### M6 — Patients Page: No Content Visible
**Page:** `/patients`  
**Problem:** Screenshot shows the patients page is either blank or has no meaningful content visible above the fold. If this is a placeholder page, it should show a "Coming soon" or "Not yet configured" state rather than a blank area.  
**Fix:** Add an explicit placeholder state: "Patient lookup is not yet connected to EMIS. Coming in Phase 2." with relevant context.

### M7 — Page Titles Are Inconsistent
**Pages:** Various  
**Found:**
- Dashboard: `Dashboard - JeffLocal` (hyphen separator)  
- Staff: `Staff Management — JeffLocal` (em-dash separator)  
- Settings: `Settings — JeffLocal` (em-dash)  
- Login: `Sign in — Churchtown Medical Centre` (em-dash, different product name)  
**Fix:** Standardise to `{PageName} — JeffLocal` (em-dash throughout). The login page showing "Churchtown Medical Centre" instead of "JeffLocal" is intentional (practice branding) — document this as by-design if so.

### M8 — Dashboard Analytics Sidebar "QUICK STATUS" Heading Lacks Semantic Role
**Page:** Dashboard sidebar  
**Problem:** "QUICK STATUS", "STAFF WORKLOAD", "CALL ANALYTICS" section headings appear to be generic `<div>` or `<span>` elements styled to look like headings (uppercase, small). They are not `<h3>` or similar — they do not appear in the heading hierarchy (`heading-order` audit only found H1 and H2 elements).  
**Fix:** Use `<h3>` for sidebar section headings so screen reader users can navigate to "Staff Workload" directly.

### M9 — `outline: none` Should be Replaced with `focus-visible`
**Already listed as C2** — included here to emphasise the CSS fix approach:
```css
/* Remove this: */
*:focus { outline: none; }

/* Add this: */
*:focus-visible { outline: 2px solid #0891B2; outline-offset: 2px; border-radius: 2px; }
```

### M10 — Staff Management Page: Add/Edit Form Accessibility
**Page:** `/staff`  
**Problem:** Staff creation form likely uses form elements that may not be fully keyboard navigable or announced correctly. Audit was unable to verify because form was not in a visible state during snapshot.  
**Recommendation:** Run a dedicated form audit on the Add Staff flow: label association, error announcement, required field marking, and submit button state during submission.

### M11 — Reports Page Layout
**Page:** `/reports`  
**Problem:** Screenshots show the reports page with dense tabular data. At 768px tablet width, tables may require horizontal scroll but no visible scroll indicator or `overflow-x: auto` wrapper was confirmed.  
**Fix:** Wrap all data tables in `<div class="overflow-x-auto">` and test at 768px.

## LOW Priority (Quality of Life)

### L1 — No Keyboard Shortcut Hints
Staff who use the dashboard all day would benefit from keyboard shortcuts (e.g. `R` to start review, `S` to save, `/` to search). Not a blocker, but reduces friction significantly for power users.

### L2 — Session Timeout Not Visible
**DCB0129 H4 note from Lead Agent:** The session timeout (60 minutes) is set but there is no visible countdown or warning before expiry. Staff filling in long outcome notes may lose their work without warning.  
**Fix:** Show a "Your session will expire in 5 minutes" toast with a "Stay signed in" button when the session has 5 minutes remaining.  
**Note:** This touches session behaviour — Saeed approval required before implementation.

### L3 — "Start Review" Button on Case List Row
**Page:** `/requests`  
**Problem:** "Start Review" appears twice — once as a row-level button and once in the bulk action bar. Their visual hierarchy is the same. It's not clear which one applies to the bulk selection.  
**Fix:** Style the bulk action bar distinctly (sticky bottom bar, different background) to separate individual vs batch actions.

### L4 — Audit Tab on Case Detail
**Page:** `/case/{id}` — Audit tab  
**Problem:** The audit trail is important for accountability (DCB0129 H4) but is hidden behind a tab. Staff may not know it exists.  
**Recommendation:** Show a small "Last action by X at Y" summary line directly on the case header, outside the tab panel.

### L5 — Print / Export Styles
**All pages:** No print stylesheet detected. If staff need to print case summaries for handoff (e.g. urgent cases during system outage), the current layout would print the sidebar and all navigation chrome alongside the case content.  
**Fix:** Add `@media print { .cd-sidebar, .cd-header, .cd-action-bar { display: none; } }` and test print output.

### L6 — Dark Mode Not Detected
The dashboard has no dark-mode (`prefers-color-scheme: dark`) CSS. While this is not critical for a clinical tool, late-night reception shifts (out-of-hours service) would benefit from a reduced-brightness mode. Low priority but worth noting for future.

### L7 — "Resolved Today: 0" Baseline Counter Missing Context
**Page:** Dashboard  
**Problem:** "Processed Today: 0" shows next to "Open Cases: 10" with no explanation of what "processed" means in context (is this pipeline processing or staff resolution?). Could cause confusion.  
**Fix:** Add a tooltip or short label clarification: "Processed Today (pipeline)" vs "Resolved Today (staff)".
