End-to-End: Patient Call → Reception Action
1
Patient calls the surgery
Jeff (Hostcomm UK voice AI) answers. Captures the reason for the call in plain language. Jeff does NOT make any clinical decisions — it only records what the patient says.
EXTERNAL — Hostcomm UK
2
Encrypted intake arrives
Jeff sends the transcript as an encrypted JSON payload via n8n webhook. n8n (port 5678, webhook path: ava-live-intake) receives it and writes it to the queue.
queue/encrypted_raw/
3
Pipeline processes the transcript
PowerShell pipeline decrypts, validates HMAC signature, then calls Ollama/Gemma (gemma4:e2b) to extract structured data from the patient's words. Fallback to gemma4:e4b if confidence < 0.72.
scripts/process_queue.ps1 → scripts/call_ollama.ps1
4
Deterministic safety layer
All LLM output is VERIFIED by deterministic code. The following fields are ALWAYS set by code — NEVER by the AI: priority, matched_patient_name, EMIS number, NHS number, date of birth, verification_status, safe_to_queue.
scripts/evaluate_model_output.ps1 → scripts/build_handoff.ps1
🛡️ SAFETY GATE
5
Handoff JSON written
Verified task written as a structured JSON file. Contains: patient reference, reason, priority, safe_to_queue flag, and metadata.
outputs/handoff_json/
6
Dashboard importer picks it up
The dashboard background importer polls outputs/handoff_json/ every few seconds. Imports verified tasks into SQLite. Each task is tagged with practice_id for multi-tenancy isolation.
dashboard/app/importer.py → dashboard/data/dashboard.sqlite
7
Reception staff action the task
Staff log in to the dashboard at https://dashboard.app-avamed.uk. They see prioritised tasks, click through to case detail, mark as actioned. Audit log captures every action with timestamp and user.
dashboard/ → Port 8765 → Cloudflare tunnel → dashboard.app-avamed.uk
LIVE PRODUCTION
8
Adding a new practice (multi-tenancy)
New practice = one database row. No new server, no new codebase, no new deployment. Practice gets login credentials and is visible only to their own staff via practice_id isolation on all queries.
ONE SYSTEM, MANY PRACTICES
